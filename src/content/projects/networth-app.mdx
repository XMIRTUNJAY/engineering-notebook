## What

Wealthpath answers one question honestly: *where do I stand, and when can I stop?* Assets, liabilities, goals, and transactions CRUD. A 4-step monthly check-in wizard. Forecasting with optimistic/expected/conservative bands plus seeded Monte Carlo p10/p50/p90. What-if scenarios, a standalone calculator suite, CSV/Excel import, full JSON export, and opt-in Postgres cloud sync. Solo-user, desktop/self-host oriented.

## Why this shape

Four constraints drove every decision: financial data must work with zero cloud dependency; a solo user means sync can be last-write-wins; money math must be unit-tested; deployment must be a SQLite file plus `next start`. The result: three storage backends behind one fetch interposer (`local-bridge.ts`), a framework-free calculation engine (`src/lib/engine/`), and 21 API route files with zod validation. Details live in the tutorial series below.

<Callout type="decision" title="Why three databases">
  A single hosted database would violate the privacy constraint; localStorage-only would cap query power and durability. So: server SQLite with migrations, a browser IndexedDB mirror, and Postgres purely for opt-in sync.
</Callout>

## Constraints

Extracted from the implementation, not aspired to:

- Must work with zero cloud dependency (local mode via Dexie mirror).
- Data must remain private (SQLite file + optional self-hosted sync).
- Calculations must be deterministic and testable (seeded engine, 40 unit tests).
- Must support Excel/CSV import (dependency-free RFC-4180 parser + SheetJS wrapper).
- Deployment must be one file plus one command (`next start` standalone + SQLite).

## Engineering decisions

<Decision
  title="Snapshots as source of truth"
  problem="Net worth must be auditable and recomputable, not a number that drifts."
  options={["Store computed net worth directly", "Derive from monthly per-asset snapshots", "Event-sourced ledger of every change"]}
  chosen="Derive from snapshots; history table is a recalculated cache with no write route."
  why="Snapshots are human-meaningful (one value per asset per month) and make every derived number reproducible from inputs."
  tradeoffs="Two recompute paths (server recalc + client context) must be kept consistent; the 2025-09-01 audit flagged this as the top drift risk."
  result="Change decomposition (contributions vs growth) falls out for free; export/restore stays coherent."
/>

<Decision
  title="Seeded Monte Carlo bands instead of point forecasts"
  problem="Single-number projections pretend certainty the market never offers."
  options={["Deterministic compound projection only", "Monte Carlo with fixed seed", "Full stochastic model with fitted distributions"]}
  chosen="LCG + Box-Muller simulation, 1000 paths, p10/p50/p90 output, seed parameter."
  why="Seeded runs are bit-identical (measured), which makes statistical code unit-testable; bands communicate uncertainty honestly."
  tradeoffs="LCG quality is fine for projections, not cryptography; inflation input is computed but not yet wired into the path."
  result="~31 ms per run; UI recomputes per keystroke; tests assert exact outputs."
/>

## What didn't work

Two documented before/after stories, both evidenced in the repo — no manufactured failures:

**Attempt 1: health score v1.** `src/lib/finance.ts` computed health from allocation heuristics with weights totaling 95 and a goal component driven by milestone progress rather than goals. The audit called it half-fudged. **Final approach:** `src/lib/engine/health.ts` v2 — seven transparent sub-scores (liquidity, savings, debt, emergency, goals, diversification, history) weighting to exactly 100, with 2 unit tests pinning near-full and zero states.

**Attempt 2: untested math layer.** The audit found no test framework installed at all. **Final approach:** the `engine/` split plus 9 vitest files, 40/40 passing (run 2026-09-04), with coverage mapping exactly onto the modules that matter.
